# 架构设计

## 一、设计目标

1. **功能不减**：老项目的全部功能点保留，只改变命名与组织方式。
2. **去阶段化**：不再按高中 / 大学 / 职场切分模块，所有数据属于同一个用户。
3. **建立关联**：用一条「拾光时间线」把记录、学习、规划、社区、档案的数据聚合起来，跨域可跳转。
4. **DDD 化**：后端按限界上下文分模块，模块内部严格四层，依赖方向单一。
5. **好跑**：模块化单体，单启动类单端口，本地一条命令跑通全链路。

## 二、限界上下文

| 上下文 | 聚合根 / 主要实体 | 职责 |
|---|---|---|
| identity | Account、AuditLog、UserProfile、ResumeSection | 认证、账号、角色、个人中心、管理后台、审计 |
| timeline | LifeRecord、Milestone、GrowthLink、WorkRecord、AdvanceRecord | 时间线原始数据、里程碑与贯通关联 |
| learning | Question、AnswerRecord、MistakeRecord、ScoreRecord、PracticeSession | 题库、练习、错题、成绩、图谱 |
| planning | SubjectOption、CourseSelection、VolunteerPlan、TermCourse 等 17 个 | 选科、志愿、课程学分、目标与复习 |
| archive | Certificate、Paper、CourseTreeNode 等 6 个 | 简历、证书、课程树、论文 |
| community | Content、ContentComment、LikeRecord、FavoriteRecord | 内容、评论、互动、文章图谱 |
| file | 文件系统（无数据库实体） | 上传与删除 |

模块之间原则上**不直接互相依赖**。跨域聚合（`/api/v1/timeline/feed`、`/api/v1/dashboard`）放在
`launcher` 装配层，它依赖所有上下文，符合「外层依赖内层」的方向。
唯一例外是 `archive → identity` 的单向依赖：「完整简历」接口需要读取 identity 上下文的
`resume-sections`，故 `archive/pom.xml` 显式声明 `cot-identity`；identity 不反向依赖 archive，
不会形成环。若后续跨域查询增多，建议把这类查询上移到 `launcher` 或通过 `api` 模块定义查询端口。

## 三、四层结构

```
interfaces/          REST 控制器：统一资源接口 + 领域特性接口
      ↓
application/         应用服务：编排仓储、账号隔离、关键词过滤、统计、rows() 视图
      ↓
domain/
  model/              领域实体（@TableName 持久化模型）
  repository/         仓储接口（依赖倒置）
      ↑ 实现
infrastructure/
  persistence/        MyBatis-Plus Mapper + RepositoryImpl
```

`common-core` 提供 `Repository<T, ID>` 契约与 `BaseMapperRepository<T, M>` 通用实现，
以及 `AuthContext`（业务服务不反向依赖 identity）、`AccountLookup` 端口（由 identity 实现）。

## 四、时间线聚合

`TimelineFeedController` 把 11 类数据（记录、里程碑、工作、进阶、成绩、练习、规划、目标、
文章、证书、论文）统一映射为 `{type, occurredAt, title, summary, link, color, sourceId}`，
按时间倒序返回。前端每个节点可跳回来源功能，实现「功能之间有关联」而不是「功能被切成三段」。

前端主导航按 5 个功能域（时间线 / 学习 / 规划 / 社区 / 档案）组织，悬停弹出 Mega Menu。

## 五、认证与权限

- `AuthInterceptor` 把路径分三级：PUBLIC（登录、注册、公开洞察）、AUTHENTICATED、ADMIN。
- 每次受保护请求验签后回查账号 `status / role / token_version`，因此退出、停用、改密、重置密码都会立即吊销旧令牌。
- 未登记的路径仍是真正的 404，不会被鉴权层改成 401。
- 自助注册强制 `USER`；管理员由内置数据或后台创建。
- 业务资源默认按 `user_id` 隔离；管理员显式 `all=true` 可跨账号核查。

## 六、运行形态与演进

当前是**模块化单体**：10 个 library jar + 1 个 `launcher` 可执行 jar，端口 8080。
Spring Cloud / Redis 依赖保留但默认关闭（`spring.cloud.enabled: false`）。
当某个上下文成为瓶颈时，给它补回启动类与配置即可拆成独立微服务，业务代码不用改。

## 七、数据一致性

单库单 DataSource，MyBatis-Plus 承担 CRUD，Flyway `V1__schema.sql` 建表、`V2__seed_demo.sql` 写演示数据。
表名沿用老项目命名，保证已有数据可以平滑迁移；Java 包名、artifactId、前端路由全部改为中性命名。
