# 开发指南

## 环境

| 工具 | 版本 |
|---|---|
| JDK | 编译目标 17，本机验证使用 JDK 24.0.1 / Maven 3.9.x |
| Maven | 3.8+ |
| Node | 20+（本机 Node 22.22.2） |
| MySQL | 8（`dev` profile 可用 H2 免安装） |
| Redis | 可选，懒连接；未启动不影响应用启动 |

## 后端

```bash
cd back-end-spring-cloud
mvn -B clean package                 # 12 个 Reactor 模块 + 单元测试
java -jar launcher/target/cot-launcher-0.1.0-SNAPSHOT.jar --spring.profiles.active=dev
```

默认 profile 为 `mysql`，连接参数走环境变量：

| 变量 | 默认值 |
|---|---|
| `COT_DB_URL` | `jdbc:mysql://localhost:3306/chronicles_of_time?...` |
| `COT_DB_USER` / `COT_DB_PASSWORD` | `root` / 空 |
| `COT_AUTH_SECRET` | 开发默认值（**生产必须覆盖**） |
| `COT_UPLOAD_DIR` | `./uploads` |
| `COT_REDIS_HOST` / `COT_REDIS_PORT` | `localhost` / `6379` |
| `COT_PROFILE` | `mysql`（可设 `dev`） |

`./data` 与 `./uploads` 相对 **JVM 工作目录**解析：建议在 `back-end-spring-cloud/` 下启动，
并统一 IDEA 的 Working directory，避免 H2 库看起来「不见了」。

### 端口冲突与环境变量覆盖

- 默认 `server.port: 8080`。若参考项目 `AdmitAtlas` 正在 IDEA 中运行，它会占用 8080，
  新项目启动会报 `Port 8080 was already in use`，或者前端请求打到老服务而全部返回 404。
  换端口启动并同步修改 `front-end/vite.config.js` 两处 proxy `target`：
  ```bash
  java -jar launcher/target/cot-launcher-0.1.0-SNAPSHOT.jar \
    --spring.profiles.active=dev --server.port=18080
  ```
- 部分 IDE / 本地代理会注入 `SERVER__PORT`（如 `58693`），Spring Boot 的松散绑定会把它
  当成 `server.port` 并覆盖配置文件，导致服务起在意料之外的端口。命令行 `--server.port=...`
  优先级最高，可强制锁定；也可启动前清除该变量（bash `unset SERVER__PORT`，
  Windows `set SERVER__PORT=`）。

## 前端

```bash
cd front-end
npm install
npm run dev       # 5173，/api 与 /files 代理到 8080（改后端端口时同步改 vite.config.js）
npm run build     # dist/
npm run preview
```

若 `npm install` 报 `403 Forbidden`（部分网络环境会拦截 `registry.npmmirror.com`），
可切换官方源 `npm config set registry https://registry.npmjs.org`；
本机验证时因 registry 被拦截，`node_modules` 是从 `AdmitAtlas/front-end/node_modules`
复制而来（依赖版本与 `package.json` 一致），因此没有生成 `package-lock.json`。
克隆仓库后请在自己网络环境下重新执行一次 `npm install` 以生成锁文件。

## 常见问题

- **启动报 `Port 8080 was already in use` 或接口全 404**：8080 多半被 `AdmitAtlas` 占用，
  或 `SERVER__PORT` 环境变量覆盖了配置；见上文「端口冲突与环境变量覆盖」。
- **Flyway checksum mismatch**：不要修改已应用的 `V1__schema.sql` / `V2__seed_demo.sql`，
  需要改数据请新增 `V3__*.sql`。
- **MySQL 连不上**：先用 `--spring.profiles.active=dev` 跑 H2 验证链路，再检查 `COT_DB_*`。
- **401 后立即跳登录**：这是预期行为；检查 `COT_AUTH_SECRET` 是否与签发时一致。
- **上传文件访问 404**：确认 `COT_UPLOAD_DIR` 与启动工作目录一致，且 `/files/**` 未被网关拦截。
- **手写体缺字**：`MaShanZheng.woff2` 是按需子集，新增手写文案要重新生成字体子集。

## 新增功能的步骤

1. 在对应上下文的 `domain/model` 加实体、`domain/repository` 加接口、
   `infrastructure/persistence` 加 Mapper 与实现。
2. 在该上下文 `ApplicationService` 构造函数里注册资源名。
3. 在 `V3__*.sql` 加建表脚本（表结构变化必须走新迁移）。
4. 前端在 `api/index.js` 的 `R` 里加 `crud(ctx, res)`，页面用 `ResourcePage` 配置即可。
5. 新增写接口要在 `docs/接口说明.md` 登记权限。
