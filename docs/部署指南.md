## 1. 本地开发（不使用 Docker）

### 1.1 构建

在项目根执行即可（`-f` 指向聚合 POM）：

```bash
mvn -B -f back-end-spring-cloud/pom.xml clean package
```

产物为 `back-end-spring-cloud/launcher/target/cot-launcher-0.1.0-SNAPSHOT.jar`。

### 1.2 方式一：MySQL（默认 `mysql` profile）

`application.yml` 默认激活 `mysql` profile，数据源 URL 自带 `createDatabaseIfNotExist=true`。**密码必须显式提供**，默认空密码会导致 `Access denied`：

```bash
# Linux / Git Bash
export COT_DB_USER=root
export COT_DB_PASSWORD='<你的本机 MySQL 密码>'
# Windows CMD:  set COT_DB_PASSWORD=<你的密码>

java -jar back-end-spring-cloud/launcher/target/cot-launcher-0.1.0-SNAPSHOT.jar
```

需要改连接串时覆盖 `COT_DB_URL`（本机主机名是 `localhost`）。若本机没有 MySQL，可先只起依赖：

```bash
docker compose -f back-end-spring-cloud/deploy/docker-compose.yml up -d mysql redis
```

### 1.3 方式二：H2（`dev` profile，零外部依赖）

```bash
java -jar back-end-spring-cloud/launcher/target/cot-launcher-0.1.0-SNAPSHOT.jar \
  --spring.profiles.active=dev
```

使用 H2 文件库 `./data/cot` 与**同一套 Flyway 迁移**，并开启 `/h2-console`。适合无 MySQL / Redis 的功能演示。注意 H2 数据文件位于 JVM 工作目录下（相对 `back-end-spring-cloud/`），已被 `.gitignore` 排除。

### 1.4 前端 dev server、Vite 代理与端口冲突

```bash
cd front-end
npm ci          # 需要 front-end/package-lock.json
npm run dev     # http://localhost:5173
npm run build   # 产物 front-end/dist/
```

`front-end/vite.config.js` 把 `/api` 与 `/files` 代理到 `http://localhost:8080`，因此**前端 dev 与后端必须同时启动**，且后端必须在 8080。

容易冲突的端口：

| 端口 | 占用者 | 处理 |
|---|---|---|
| `8080` | 后端 | 见 §6.1；改端口后须同步改 Vite 代理 `target` |
| `5173` | Vite dev server | compose 的 `web` 默认也映射宿主机 `5173`，**二者不要同时运行**；或用 `COT_WEB_PORT` 改 compose 映射 |
| `3306` / `6379` | MySQL / Redis | 本机已装同名服务时，改用 compose 内的服务或停掉本机实例 |

### 1.5 验证

```bash
curl http://localhost:8080/actuator/health
curl http://localhost:8080/api/v1/system/modules
curl http://localhost:8080/api/v1/dashboard
# 登录后可验证横切端点（把 <TOKEN> 换成 /api/v1/auth/login 返回的 token）
curl -H "Authorization: Bearer <TOKEN>" "http://localhost:8080/api/v1/search?q=%E6%97%B6%E9%97%B4%E7%BA%BF"
# V9 写入的演示分享链接（免登录）
curl http://localhost:8080/api/v1/timeline/share/demo-share-token-2026
```

迁移核对（真实 MySQL 8）：启动后查 `flyway_schema_history`，应有 V1–V9 且 `success = 1`。
V6–V9 分别新增：里程碑来源与答题场次字段、免登录分享表、内容审核字段、与新功能对齐的演示数据；
V9 会把 V3 种子里的英文枚举（`DONE/TODO/IN_PROGRESS`、`调研/开发`、`CATEGORY/COURSE`）精确替换为
批次 4 中文看板与课程树所用的取值，不会覆盖用户自定义的其它取值。

## 2. Docker Compose 一键启动

### 2.1 命令

**必须从项目根执行**（`-f` 指向 `deploy/` 下的文件，compose 中的 `../..`、`./mysql-data` 都相对该文件所在目录解析）：

```bash
docker compose -f back-end-spring-cloud/deploy/docker-compose.yml up -d --build
```

其余常用命令：

```bash
# 只看渲染后的配置（不构建、不启动，适合排错）
docker compose -f back-end-spring-cloud/deploy/docker-compose.yml config

# 查看日志
docker compose -f back-end-spring-cloud/deploy/docker-compose.yml logs -f backend web

# 查看健康状态
docker compose -f back-end-spring-cloud/deploy/docker-compose.yml ps

# 停止并移除容器（默认保留 volume，数据不丢）
docker compose -f back-end-spring-cloud/deploy/docker-compose.yml down
```

`backend` 通过 `command: ["--spring.profiles.active=prod"]` 激活 **`prod` profile**（命令行参数优先级高于 `application.yml` 里的 `spring.profiles.active`）。

### 2.2 四个服务与端口

| 服务 | 镜像 / 构建 | 容器端口 | 宿主机默认端口 | 说明 |
|---|---|---|---|---|
| `mysql` | `mysql:8.0` | 3306 | `3306` | 库 `chronicles_of_time`，数据卷 `./mysql-data` |
| `redis` | `redis:7-alpine` | 6379 | `6379` | 懒连接，健康检查 `redis-cli ping` |
| `backend` | `deploy/Dockerfile.backend` 多阶段构建 | 8080 | `8080` | 唯一可执行 jar，`prod` profile |
| `web` | `deploy/Dockerfile.frontend` 多阶段构建 | 80 | `5173`（`COT_WEB_PORT` 可覆盖） | nginx 托管 SPA + 反代 |

> 两个 `build.context` 都是 `../..`（项目根），`dockerfile` 路径为 `back-end-spring-cloud/deploy/Dockerfile.backend` 与 `.../Dockerfile.frontend`。**不要从 `deploy/` 目录直接执行**，否则相对路径会错。

### 2.3 访问地址

| 入口 | 地址 |
|---|---|
| 前端页面（经 nginx） | `http://localhost:5173/`（或 `http://localhost:${COT_WEB_PORT}/`） |
| 前端调用后端（经 nginx 反代） | `http://localhost:5173/api/v1/...` |
| 后端直连（调试用） | `http://localhost:8080/api/v1/...` |
| 健康检查 | `http://localhost:8080/actuator/health` |
| 上传文件 | `http://localhost:5173/files/...` 或 `http://localhost:8080/files/...` |

### 2.4 healthcheck 与启动顺序

| 服务 | 探测命令 | 作用 |
|---|---|---|
| `mysql` | `mysqladmin ping -h 127.0.0.1 -uroot -p$$MYSQL_ROOT_PASSWORD` | 确认可接受连接 |
| `redis` | `redis-cli ping` | 确认可用 |
| `backend` | `wget -q --spider http://localhost:8080/actuator/health` | 确认应用就绪 |
| `web` | 无 | 仅 `depends_on: [backend]` |

`backend.depends_on` 对 `mysql` / `redis` 使用 `condition: service_healthy`，避免应用在数据库尚未就绪时启动导致 Flyway 迁移失败。`backend` 的探针使用 `wget`，`Dockerfile.backend` 的运行阶段已显式安装 `wget` 以保证探针可用；`start_period: 60s` 给 Spring Boot 启动 + Flyway 迁移留出时间。

> `web` 的 `depends_on` 是短语法（只等容器启动，不等 backend 健康）。首次启动时若页面报 502，等 `/actuator/health` 变为 `UP` 后刷新即可。

## 3. 生产环境变量清单

`application-prod.yml` 依赖下列变量。**compose 中的默认值全部「仅用于本地开发一键启动」，生产必须逐一替换为环境变量 / Docker secrets / CI 注入**，不要把 `.env` 或 `cot-local.yml` 提交进仓库。

| 变量 | 用途 | compose 本地默认值 | 生产要求 |
|---|---|---|---|
| `COT_DB_URL` | JDBC 连接串 | `jdbc:mysql://mysql:3306/chronicles_of_time?...` | 主机名在容器内是 `mysql`；外网部署换成真实地址与库名 |
| `COT_DB_USER` | 数据库用户 | `root` | 使用最小权限专用账号 |
| `COT_DB_PASSWORD` | 数据库密码 | `cot_dev_password` | **必须替换**，走 secrets |
| `COT_AUTH_SECRET` | JWT 签名密钥 | `cot-LOCAL-DEV-ONLY-change-me-before-production` | **必须替换**，见下方 |
| `COT_AUTH_TTL_HOURS` | Token 有效期（小时） | `12` | 按安全策略调整 |
| `COT_REDIS_HOST` | Redis 主机 | `redis` | 容器内服务名或外部地址 |
| `COT_REDIS_PORT` | Redis 端口 | `6379` | — |
| `COT_REDIS_PASSWORD` | Redis 密码 | 空 | 生产应设密码并同步给 redis 服务 |
| `COT_UPLOAD_DIR` | 上传目录 | `/app/uploads` | 与 volume 挂载点一致 |
| `COT_LOG_FILE` | 日志文件 | `/app/logs/cot.log` | 与 volume 挂载点一致 |
| `COT_SERVER_PORT` | 应用监听端口 | `8080` | 见下方端口一致性说明 |
| `COT_HEALTH_REDIS_ENABLED` | 是否把 Redis 纳入健康指示器 | `true` | Redis 不可用时可设 `false` |

另外两个 compose 层变量：`MYSQL_ROOT_PASSWORD`（默认 `cot_dev_password`，**必须替换**）、`COT_WEB_PORT`（默认 `5173`，仅影响宿主机映射端口）。

### `COT_AUTH_SECRET` 必须替换

`prod` profile 中该变量**没有默认值，缺失会直接启动失败**。它用于 HS256 JWT 签名，泄露即可伪造任意用户身份。生产请：

1. 用密码学安全随机源生成，例如 `openssl rand -hex 32`；
2. 通过环境变量 / Docker secrets / CI secret 注入，**不要写进任何被提交的文件**；
3. 定期轮换（轮换会使所有已签发 token 失效，需配合用户重新登录）。

### 端口一致性

容器内部端口固定 `8080`：它同时出现在 `Dockerfile.backend` 的 `EXPOSE 8080`、`nginx.conf` 的 `proxy_pass http://backend:8080` 与 `ports: "8080:8080"` 中。

- 只想改**宿主机**访问端口：改 `ports` 左侧即可（如 `"8081:8080"`），nginx 通过服务名访问容器，**无需改动 nginx.conf**；
- 若改 `COT_SERVER_PORT`（容器内监听端口），则必须同步改 `EXPOSE`、`nginx.conf` 的 `proxy_pass` 与 `ports` 右侧，否则会出现 502 / 连不上。故本地部署不建议改这个变量。

## 4. 前端静态资源如何经 nginx 反代到后端

`Dockerfile.frontend` 分两阶段：

1. **build**：`node:20-alpine`，先 `COPY front-end/package*.json` 并 `npm ci`（利用层缓存），再复制 `front-end/` 源码执行 `npm run build`，产出 `/build/dist/`；
2. **run**：`nginx:alpine`，把 `dist/` 复制到 `/usr/share/nginx/html/`，并把 `deploy/nginx.conf` 覆盖为 `/etc/nginx/conf.d/default.conf`。

`nginx.conf` 的关键规则：

- `location /` 使用 `try_files $uri $uri/ /index.html`，保证 SPA 的 history 路由（如 `/timeline/123`）刷新不 404；
- `location ^~ /api/` 与 `location ^~ /files/` 用 `proxy_pass http://backend:8080` 反代到后端。`proxy_pass` **不带尾斜杠**，因此 `/api/v1/...` 路径原样透传；`backend` 是 compose 服务名，由容器网络 DNS 解析；
- 两组反代都设置了 `Host`、`X-Real-IP`、`X-Forwarded-For`、`X-Forwarded-Proto`，便于后端记录真实客户端信息；
- `/assets/`（带内容 hash）长缓存 `immutable`，其它静态资源缓存 7 天；`index.html` 设 `no-cache`，避免发版后浏览器仍引用旧资源；
- `client_max_body_size 20m` 与后端 `spring.servlet.multipart.max-file-size: 20MB` 对齐。

> 上传请求体含 multipart 边界开销，接近 20MB 的单文件可能略超 20m；如遇 413，可把 `client_max_body_size` 调大到 `25m`（后端 `max-request-size` 为 40MB，有余量）。

## 5. 数据持久化与备份

| 数据 | 存储方式 | 位置 |
|---|---|---|
| MySQL 数据 | bind mount | `back-end-spring-cloud/deploy/mysql-data/`（相对 compose 文件） |
| 上传文件 | named volume | `cot-uploads` → `/app/uploads` |
| 应用日志 | named volume | `cot-logs` → `/app/logs` |

注意点：

- `mysql-data/` 已被 `.gitignore` 与项目根 `.dockerignore` 排除，不会进 git 也不会进镜像构建上下文；
- **上传文件不在数据库里**，备份数据库时别忘了同时备份 `cot-uploads`；
- `docker compose down` 默认**保留** volume；`down -v` 会删除 named volume 导致上传文件与日志丢失，谨慎使用（MySQL 是 bind mount，`-v` 不会删它）；
- 逻辑备份示例（在宿主机执行，密码从环境变量读取，不要写进脚本）：

```bash
docker compose -f back-end-spring-cloud/deploy/docker-compose.yml exec mysql \
  sh -c 'mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --single-transaction chronicles_of_time' \
  > backup_$(date +%F).sql
```

- 若要直接复制 `mysql-data/`，**必须先停库**（或 `--single-transaction` + 一致性快照），否则可能得到不一致的数据文件；
- 生产建议把 MySQL 换成托管数据库，并单独规划定时备份与恢复演练。

## 6. 常见问题（FAQ）

### 6.1 `8080` 被占用

现象：`Web server failed to start. Port 8080 was already in use.` 或 compose 端口映射失败。

- 查找占用：Windows `netstat -ano | findstr :8080`；Linux `ss -ltnp | grep 8080`；
- 本地 jar 启动：加 `--server.port=8081`（或 `prod` profile 下设置 `COT_SERVER_PORT=8081`），并同步改 `front-end/vite.config.js` 里 `/api`、`/files` 代理的 `target`；
- **命令行参数优先级最高**：部分 IDE / 代理会注入 `SERVER__PORT`（如 `58693`），Spring Boot 会把它松散绑定成 `server.port` 并覆盖 `COT_SERVER_PORT`，导致应用在意外端口启动甚至端口冲突。遇到这种情况用 `--server.port=8081` 强制锁定，或启动前 `unset SERVER__PORT`（Windows CMD：`set SERVER__PORT=`）；
- compose：只改 `ports` 左侧为 `"8081:8080"` 即可，nginx 反代仍在容器网络内走 `backend:8080`（见 §3 端口一致性）。

### 6.2 Redis 未启动导致 `/actuator/health` 返回 DOWN

Spring Boot 的 Redis health indicator 会把 Redis 纳入整体健康状态；Redis 连不上时 `/actuator/health` 可能整体 `DOWN`，进而影响 `backend` 的 healthcheck 与就绪判断。

- 本地 H2 / 无 Redis 演示：设置 `COT_HEALTH_REDIS_ENABLED=false` 排除该健康项；
- compose：确认 `redis` 服务已 `healthy`（`docker compose ... ps`）；`backend.depends_on.redis` 已用 `condition: service_healthy` 等待它就绪；
- 注意 `application.yml` 中 Redis 是懒连接，应用本身可以在 Redis 未就绪时启动，但健康状态会体现为 DOWN。

### 6.3 `createDatabaseIfNotExist=true` 自动建库

`COT_DB_URL` 默认带 `createDatabaseIfNotExist=true`，首次连接会自动创建 `chronicles_of_time` 库，因此**不需要手工建库**；但要求该数据库用户具备 `CREATE DATABASE` 权限。

- 建库后由 **Flyway** 执行 `V1__schema.sql` 等迁移创建表结构，不是 Hibernate DDL；
- 生产若使用受限账号或托管数据库，请预先建好库、授予必要权限，并按需从 URL 去掉该参数；
- 容器内主机名是 `mysql`（compose 服务名），本机直连才是 `localhost`，写错会报 `Communications link failure`。

### 6.4 Flyway 迁移不可回改

`launcher/src/main/resources/db/migration/` 下的 `V1__schema.sql`、`V2__seed_demo.sql`、`V3__seed_demo_expanded.sql`、`V4__seed_user_guidance.sql` 一旦在某库执行过，其校验和会记录在 `flyway_schema_history` 表中：

- **不要修改已应用的迁移文件内容**，否则启动时会 checksum 校验失败并中止；
- 需要变更结构时**新增更高版本**文件（如 `V5__xxx.sql`），不要就地改旧文件；
- **不要手工改库结构**（手工加列/改类型会让迁移历史与实际结构不一致）；
- 迁移失败会留下未完成记录，排错后可能需要 `flyway repair`（本工程未默认开启），处理前先备份数据库。

### 6.5 其它启动前置条件

| 现象 | 原因 |
|---|---|
| `npm ci` 报缺少 lock 文件 | `front-end/package-lock.json` 已提交；若被误删，在 `front-end/` 执行 `npm install --package-lock-only` 重新生成，CI 与镜像构建都用 `npm ci` |
| 后端启动即报 `Could not resolve placeholder 'COT_AUTH_SECRET'` | `prod` profile 下该变量刻意无默认值（安全设计）；compose 已给本地占位值，生产必须注入真实值 |
| 后端启动报找不到 `application-prod.yml` | 确认使用最新代码，且该配置已打进 jar：`jar tf launcher/target/cot-launcher-0.1.0-SNAPSHOT.jar \| grep application-prod` |
| 前端页面 502 | `backend` 尚未就绪；等 `/actuator/health` 为 `UP` 后刷新，并确认容器内端口仍是 8080 |
| 页面能开但接口 404 | 检查 `nginx.conf` 的 `proxy_pass` 是否**不带尾斜杠**，以及后端接口前缀是 `/api/v1/**` |

## 附：CI 校验

`.github/workflows/ci.yml` 在 push / PR 到 `main` 与手动触发时运行两个独立 job：

- `backend`：`setup-java@v4`（temurin 17，缓存 Maven）→ `mvn -B -f back-end-spring-cloud/pom.xml test`（真跑测试）→ `mvn ... package -DskipTests` → 上传 jar；
- `frontend`：`setup-node@v4`（Node 20，缓存 npm）→ 在 `front-end/` 下 `npm ci` → `npm run build` → 上传 `dist/`。

纯文档变更被 `paths-ignore` 过滤，不会触发构建。README 中的「快速开始」与本文命令保持一致；如调整端口或 profile，请同步更新本指南与 `nginx.conf`。
